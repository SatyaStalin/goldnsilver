# Third-party integrations

This note covers the partner services the API actually calls: SafeGold, Zerodha Kite Connect, Cashfree, and Sequel. It lists environment **names** and the call sequence. Secret values belong only in `backend/.env` and `frontend/.env`.

Related documents:

- [Frontend and backend structure](./frontend-and-backend.md)
- [Database structure](./database.md)

npm packages involved:

| Package | Where | Used for |
| --- | --- | --- |
| `kiteconnect` | backend | Zerodha Kite Connect session and market quotes |
| `cashfree-sdk` | backend | Cashfree orders, payments, and webhook verification |
| `razorpay` | backend and frontend | Package is installed. Live cart checkout does not open Razorpay |
| `mongoose` | backend | MongoDB |
| `jsonwebtoken`, `bcryptjs` | backend | App login, not partner login |
| `axios` | frontend | Calls this project’s API only. Partner HTTP is done on the server |

## SafeGold

SafeGold is the digital-gold partner. Code lives in:

- `backend/src/services/safegoldApi.js` — HTTP client, URLs, mock mode
- `backend/src/services/safegoldCustomerService.js` — register and map a customer
- `backend/src/services/safegoldFulfillment.js` — buy-verify and buy-confirm after payment
- `backend/src/services/safegoldService.js` — quotes, limits, wallet maths
- `backend/src/services/safegoldCrypto.js` — payload encryption
- `backend/src/routes/safegoldRoutes.js` — routes under `/api/safegold`

### Mode

`SAFEGOLD_ENV` selects staging or production. Production uses `SAFEGOLD_API_BASE_URL` when set. Staging ignores path overrides that still point at old `/v1/partners` URLs.

`SAFEGOLD_USE_MOCK=1` forces mock prices and skips live calls. If the flag is unset and `SAFEGOLD_API_KEY` is empty, the client also stays in mock. `SAFEGOLD_USE_MOCK=0` forces live behaviour even without other defaults.

`SAFEGOLD_FALLBACK_MOCK_ON_ERROR` controls whether a failed live price call may fall back to a mock quote. Set it to `0` to surface the partner error instead.

| Variable | Purpose |

| `SAFEGOLD_API_BASE_URL` | Production host |
| `SAFEGOLD_API_KEY` | Partner API key, sent on live requests |
| `SAFEGOLD_ENCRYPTION_KEY` | Encrypts sensitive partner payloads. If empty, the API key is the fallback key material |
| `SAFEGOLD_API_PATH_PREFIX` | Optional path prefix |
| `SAFEGOLD_BUY_PRICE_PATH` | Optional buy-price path override |
| `SAFEGOLD_SELL_PRICE_PATH` | Optional sell-price path. Documented default is `GET /v1/sell-price` |

| `SAFEGOLD_USERS_BALANCE_PATH` | Optional balance path |
| `SAFEGOLD_TRANSACTIONS_PATH` | Optional history path |
| `SAFEGOLD_DEFAULT_PIN_CODE` | PIN sent when the user has none. Code fallback is `400001` |
| `SAFEGOLD_REQUEST_TIMEOUT_MS` | HTTP timeout, default 5000 |
| `SAFEGOLD_MIN_INR`, `SAFEGOLD_MAX_INR` | Buy limits, defaults 1000 and 500000 |

### Identity

`partnerUserId` is the Mongo `User._id`. SafeGold returns `safegoldCustomerId`, stored on `safegoldcustomers`. A customer registered in staging cannot be reused for a production buy (`registeredEnv`).

### Buy sequence

1. `GET` buy price. The response includes a short-lived `rate_id`.
2. The app quotes grams and rupees locally from that rate, creates a `safegoldtransactions` row (`status: pending`) and an `orders` row (`orderType: safegold`).
3. The shopper pays with Cashfree.
4. After payment success, fulfillment runs **buy-verify** then **buy-confirm**. The confirmed buy transaction id is stored on `buyTxId`.
5. Wallet grams are updated from SafeGold when the account is live, or locally in mock mode.
6. The invoice is not generated by this app. `GET /v1/transactions/{tx_id}/fetch-invoice` returns a link. The API proxies that file so the dashboard iframe can show it.

Production gold-transfer (`code 21` on that call) is not part of local fulfillment. Do not add a transfer step to “complete” a buy that buy-confirm already finished.

### Sell sequence

Sell does not create a Cashfree payment. The route calls sell-verify, then sell-confirm, and stores `sellTxId` and `invoice_id`. Sell has no KYC check.

### What the UI calls

The invest pages and the customer dashboard use `safegoldService` in `frontend/src/services/api.js`. Useful backend routes include dashboard, transactions, register-customer, buy, sell, and invoice view. Invoice view accepts the JWT in the query string because an iframe cannot set `Authorization`.

## Zerodha (Kite Connect)

Zerodha is used for **market data**, not for customer login. Customer and admin login are JWT. OAuth 2 here is only the Kite Connect login.

Code lives in `backend/src/routes/zerodhaRoutes.js`, `backend/src/services/zerodhaSessionStore.js`, `backend/src/services/zerodhaMarketCache.js`, `backend/src/services/zerodhaEtfCache.js`, and `backend/src/services/metalRatesService.js`. The connect screen is `frontend/src/pages/ZerodhaIntegrationPage.jsx`.

Package: `kiteconnect`.

### Credentials

| Variable | Purpose |
| --- | --- |
| `ZERODHA_API_KEY` | Kite app key. Also placed on the login URL |
| `ZERODHA_API_SECRET` | Exchanges `request_token` for an access token. Server only |
| `ZERODHA_REDIRECT_URL` | Must match the Kite app redirect. Default is `{BACKEND_URL}/api/zerodha/callback` |
| `ZERODHA_ACCESS_TOKEN` | Optional manual token. Ignored for quotes until a session file exists, unless `ZERODHA_ALLOW_ENV_TOKEN=1` |
| `ZERODHA_ALLOW_ENV_TOKEN` | `1` to trust the env access token with no session file |
| `ZERODHA_SKIP_ENV_TOKEN` | `1` to ignore a stale env token |
| `ZERODHA_SESSION_FILE` | Where the access token and refresh material are stored. Default is a file under the backend data directory |
| `ZERODHA_RENEW_SECRET` | Protects the renew endpoint that refreshes the access token |
| `ZERODHA_VERIFY_SECRET` | Protects the session verify helper |
| `ZERODHA_GOLD_SYMBOL`, `ZERODHA_SILVER_SYMBOL` | Optional instrument overrides. Otherwise the nearest MCX future is chosen |
| `ZERODHA_GOLD_QUOTE_GRAMS` | Contract size used to turn the quote into rupees per gram. Default 10 |
| `ZERODHA_ETF_CACHE_TTL_MS` | ETF quote cache. Default 60 seconds |
| `ZERODHA_VERBOSE_LOGS` | `1` for extra logs |
| `BACKEND_URL`, `FRONTEND_URL` | Callback and the redirect back to `/zerodha-integration` |

Kite access tokens expire on Zerodha’s schedule (daily). App JWTs are unrelated and last one hour.

### Connect sequence

1. Admin or operator opens `/zerodha-integration`.
2. The API returns `https://kite.zerodha.com/connect/login?v=3&api_key=…` from `GET /api/zerodha/login-url`.
3. After Kite login, Zerodha redirects to `GET /api/zerodha/callback?request_token=…`. This route is public.
4. The server calls Kite with the API key, API secret, and `request_token`, then writes the session file.
5. The browser is sent back to `{FRONTEND_URL}/zerodha-integration` with a success or error query.
6. Quote routes use the saved session. `metalRatesService` turns the MCX gold quote into a rupee-per-gram rate for rate-linked own products. It does not invent a gold or silver price when the session is missing.

`GET /api/zerodha/callback` must stay public. The rest of `/api/zerodha` still sits behind the API token middleware except that callback.

## Cashfree

Cashfree is the only checkout used by the cart and by SafeGold buys. Implementation: `backend/src/services/paymentGateway.js` and `backend/src/routes/paymentRoutes.js`. Package: `cashfree-sdk`.

| Variable | Purpose |
| --- | --- |
| `CASHFREE_ENV` | `PRODUCTION` or the sandbox default used when this is not production |
| `CASHFREE_APP_ID` | App id |
| `CASHFREE_SECRET_KEY` | Secret. Server only |
| `FRONTEND_URL` | Used in the return URL. Default `http://localhost:5173` |
| `BACKEND_URL` | Used in the webhook URL |

Create-order return URL:

`{FRONTEND_URL}/cart?order_id={order_id}&order_status={order_status}`

Webhook:

`POST {BACKEND_URL}/api/payment/webhook`

The webhook path is public. The browser return is not a proof of payment. The cart page calls verify. Verify loads the Cashfree order and, when the order is not paid, `GET /orders/{id}/payments` for `payment_status`, `payment_message`, and `cf_payment_id`. A failed verify responds with HTTP 400 so the UI can show the full Cashfree reference and the reason. Do not shorten that reference in the banner.

Cashfree order ids are stored on `Order.paymentOrderId`.

The cart no longer starts a Razorpay checkout. `RAZORPAY_KEY_ID` and `RAZORPAY_KEY_SECRET` remain in the payment helper for older code paths only.

## Sequel

Sequel books and tracks insured physical shipments (gold, silver, and gifting). Code: `backend/src/services/sequelApi.js`, `backend/src/services/sequelService.js`, `backend/src/routes/sequelRoutes.js`.

Calls are plain `POST` JSON to `{SEQUEL_BASE_URL}` with `token` in the body. There is no Sequel npm package.

| Variable | Purpose |
| --- | --- |
| `SEQUEL_BASE_URL` | Host. Default `https://test.sequel247.com` (UAT). A host that is not the test host is treated as production |
| `SEQUEL_API_TOKEN` | Private token from Sequel. Never send it to the browser |
| `SEQUEL_FROM_STORE_CODE` | Origin warehouse. Code default `HYDNIG` |
| `SEQUEL_CLIENT_CODE` | Client code. Code default `31085` |
| `SEQUEL_ORIGIN_PINCODE` | Origin PIN for EDD |
| `SEQUEL_LOCATION` | Default `domestic` |
| `SEQUEL_SHIPMENT_TYPE` | Default `D&J` |
| `SEQUEL_SERVICE_TYPE` | Default `valuable` |
| `SEQUEL_PICKUP_DATE`, `SEQUEL_PICKUP_TIME` | Pickup window hints |
| `SEQUEL_AUTO_BOOK` | Set to `0` to stop automatic booking. Dashboard recovery can still force a book |
| `SEQUEL_ENABLED` | Optional. A non-empty token also enables the client |
| `SEQUEL_REQUEST_TIMEOUT_MS` | Default 15000 |
| `SEQUEL_INACTIVE_CACHE_MS` | How long an “account not active” response is remembered. Default 10 minutes |

### Calls in use

| Path | When |
| --- | --- |
| `POST /api/checkServiceability` | PIN check on the cart. Body field `pin_code` |
| `POST /api/shipment/calculateEDD` | Delivery estimate |
| `POST /api/shipment/create` | Book a docket after payment. Address keys must match Sequel’s sample (`consignee_name`, `address_line1`, `address_line2`, `pinCode`, `auth_receiver_name`, `auth_receiver_phone`). Extra fields such as invoice or remark have broken their portal before |
| `POST /api/track` | One docket, used by the Track button |
| `POST /api/trackMultiple` | Many dockets. Used by the 10-minute job |
| `POST /api/cancel` | Cancel a docket |
| `POST /api/create_address`, `POST /api/search_address` | Warehouse address tools |
| `POST /api/podDownload` | Proof of delivery link |

`trackMultiple` body:

```json
{ "token": "<SEQUEL_API_TOKEN>", "dockets": ["0582695036"] }
```

A HTTP 200 body has `status` `"true"` or `"false"`. Successful rows are under `successShipments`, keyed by docket number, not a plain array. Each row includes `shipment_status`, `estimated_delivery`, `br_number`, and `tracking[]` with `code` values such as `SCREATED`, `SCHECKIN`, `SPU`, and `SDELVD`. Unknown dockets come back under `errorShipments` and are stored on `sequel.lastError` without wiping a good status.

The job loads orders that have a docket and whose Sequel status is not `delivered`, `cancelled`, or `not_required`. It sends them in batches of 20. Mapping:

| Carrier signal | `sequel.status` | Order `status` |
| --- | --- | --- |
| `SDELVD` or “delivered” | `delivered` | `delivered` |
| Cancelled | `cancelled` | left as-is |
| Picked up, checked in, in transit | `in_transit` | `paid` becomes `shipped` |
| `SCREATED` only | `booked` | `paid` becomes `shipped` |

The customer dashboard Status column reads `sequel.status` for physical rows. The orders tab also refetches about once a minute while it is open, so a sync that already landed in Mongo shows up without a manual reload. Restart the backend after deploying this job so the timer starts.

UAT often returns “company status not active”. The service caches that message and still allows checkout. Booking then waits until Sequel activates the account. `node src/scripts/bookPendingSequelOrders.js` can book paid orders that never received a docket.

## What is intentionally not a live partner

- **Razorpay** is not used on the cart.
- **DigiLocker** fields exist on the KYC document for a verification flow. Manual upload is the path the KYC page completes today.
- **Email** (`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `FROM_EMAIL`) is sketched in `emailService.js` and does not send mail yet.
- **Augmont** is only a reserved digital-gold display name (`Digital Gold (Augmont)`). There is no Augmont API client.
